# Внешние команды, аргументы и подстановки

Как шаг скрипта `.nyap` превращается в запуск внешнего процесса (или нативной
команды) и как разрешаются `{плейсхолдеры}`.

## Путь выполнения

```
.nyap <steps>  →  ScriptExec.Exec  →  реестр команд (ICommandRegistry)
                                      ├─ XML-инструмент (.etool)  → ExternalExec → процесс
                                      └─ нативная команда (CodedToolBase) → Host-сервисы
```

## Разрешение команды

1. Если команду поддерживает **выбранный программатор** — берётся его команда.
2. Иначе ищется в **утилитах и встроенных** инструментах.
3. Другие программаторы неявно **не** подставляются.

## Сборка аргументов

Порядок этапов (поздние перекрывают ранние), `ScriptExec.GetArgs`:

| Этап | Источник | Пример |
|------|----------|--------|
| 0 | Пути проекта | `$dir`, `dir` (каталог проекта), `root`, `soft` |
| 1 | Аргументы скрипта | `<device value="STM32F107CGT6" />` → `{device}` |
| 2 | Опции программатора | (задел; сейчас пусто) |
| 3 | Аргументы шага | `<wflash value="fw.hex" />` → `{value}` |
| 4 | Пользовательский ввод | значения опций/полей |

После этого движок применяет **схему параметров** команды: подставляет `default`
для отсутствующих, проверяет `required` и тип (`CommandBinder`).

## Подстановка `{имя}`

`CommandTemplating.Process` заменяет `{имя}` в строке (путь и аргументы), беря
значение у `ResolveArgument(имя)`:

1. значение из аргументов (`Args.Get(имя)`);
2. иначе — правило перезаписи (алиас, см. ниже);
3. если не найдено — исключение (`no argument for param {имя}`).

Плейсхолдеры подставляются итеративно, поэтому значения могут содержать другие
`{...}`.

## Правила перезаписи (алиасы)

Задаются в `ProgEnv.LoadOptRewrite` и позволяют разным описаниям использовать
привычные имена, не дублируя значения:

| Плейсхолдер | Берётся из | Результат |
|-------------|-----------|-----------|
| `{option}` | `value` | как есть |
| `{filename}` | `value` | как есть |
| `{filenamewe}` | `value` | имя файла без расширения |
| `{optionN}` | `value` (hex-строка) | байт `N`, MSB в начале: `option0` — младший |

Пример: при `value="0A1B2C"` → `{option0}`=`2C`, `{option1}`=`1B`, `{option2}`=`0A`.

Явно заданный аргумент всегда имеет приоритет над алиасом.

## Запуск процесса

- Путь: `<path>` (или `<toolpath>` для конкретной команды).
- Если задан `<interpreter>` — запускается `interpreter <path> <command>`;
  иначе — `<path> <command>`.
- Рабочий каталог = `$dir` (каталог проекта).
- Реализация — `IProcessRunner` (ядро: `SystemProcessRunner` на `System.Diagnostics`).
  Стандартный вывод и ошибка перенаправляются, объединяются и логируются.

## Разбор результата

1. **error**-детекторы → ошибка (сообщение = найденный текст/вывод);
2. **warning**-детекторы → предупреждение;
3. иначе — успех.
4. **outputs**-правила извлекают значения в выходные переменные (см. `etool.md`).

Выходные переменные вливаются в окружение запуска и доступны следующим шагам.

## Нативная команда `external`

Встроенный инструмент **External** запускает произвольную программу. Значение
`value` — строка `"программа.exe аргументы"` (разделитель — `.exe`):

```xml
<external value='notepad.exe "{filename}"' />
```

Подстановка `{...}` выполняется так же, затем запуск через `IProcessRunner`.

## Встроенные нативные команды

| Команда | Инструмент | Назначение |
|---------|-----------|------------|
| `copy`, `copyto`, `delete` | FileTools | файловые операции |
| `message`, `question` | Messages | диалоги (`IUserInterface`) |
| `external` | External | запуск внешней программы |
| `download`, `lookup` | Net (плагин) | сеть (см. `NyaProg.Modules.Net/README.md`) |

## Примеры

Программатор (`.etool` + `.nyap`):

```xml
<!-- stlink_stm32.etool -->
<wflash><command value='-c {interface} UR -Q -P "{filename}" -V -Rst' /></wflash>
```
```xml
<!-- project.nyap -->
<steps><wflash value="hub_application.hex" comment="Прошивка ПО" /></steps>
```
При выборе интерфейса SWD итог: `-c SWD UR -Q -P "hub_application.hex" -V -Rst`.

Утилита-конвертер с параметрами по умолчанию:

```xml
<bintoalf>
  <command value='-i{option} -o{option}.alf -v{version} -e{oem} -d{name}' />
  <params>
    <version default="0x0000" />
    <oem default="0x0000" />
    <name default="Firmware" />
  </params>
</bintoalf>
```
Отсутствующие `{version}`/`{oem}`/`{name}` подставятся из `default`.

См. также: [Формат `.etool`](etool.md).
