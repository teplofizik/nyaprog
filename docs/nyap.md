# Формат `.nyap` — прошивочный проект

`.nyap` — XML-описание проекта прошивки: что прошивать, какими командами и с
какими параметрами. Проект содержит одну или несколько **целей** (контроллеров,
`<target>`); каждая цель — последовательность **шагов** (команд). Если цель одна —
её выбор в интерфейсе пропускается.

Элемент `<script>` поддерживается как устаревший синоним `<target>`.

## Где лежат

`Projects/<папка>/<файл>.nyap` — путь задаётся в `config.xml` секцией `<projects>`.
Каталог файла считается рабочим (`{dir}`) — оттуда берутся файлы прошивок.

## Структура проекта

```xml
<project>
  <name value="2022.12.28. Хаб" />
  <description value="Контроллер хаба терминала" />
  <date value="2022-12-28" />           <!-- дата создания (для списка проектов) -->
  <photo value="board.png" />           <!-- изображение проекта (относительно каталога) -->
  <readme file="readme.txt" />          <!-- или value="текст" -->
  <type value="stm32" />                <!-- архитектура (выбор программатора) -->
  <tag value="stm32" />

  <options> ... </options>              <!-- опции уровня проекта (см. etool.md) -->

  <target> ... </target>                <!-- одна или несколько целей-контроллеров -->
</project>
```

| Элемент | Назначение |
|---------|-----------|
| `name` | название проекта (в списке) |
| `description` | краткое описание |
| `date` | дата создания (для карточки в списке) |
| `photo` | изображение проекта (путь относительно каталога проекта) |
| `readme` | подробное описание: `file="..."` (относительно проекта) или `value="..."` |
| `type` | поддерживаемые архитектуры; по ним подбираются программаторы |
| `tag` | теги |
| `options` | опции, показываемые пользователю (как в `.etool`) |
| `target` | цель — контроллер (может быть несколько) |

## Цель (`<target>`)

```xml
<target>
  <name value="Основной МК" />          <!-- название цели (в списке контроллеров) -->
  <description value="Краткое описание" />  <!-- краткое описание цели -->
  <photo value="main.png" />            <!-- фото платы для визуального сравнения -->
  <cathegory value="0" />               <!-- группировка целей -->
  <device value="STM32F107CGT6" />      <!-- прочий элемент → аргумент {device} -->
  <id value="20240814_getline" />       <!-- прочий элемент → ключ предпочтений -->
  <type value="pic" />                  <!-- необязательно: переопределить архитектуру проекта -->
  <readme value="..." />
  <options> ... </options>

  <input value="int" default="0" id="getcall.counter" autoincrement="1" />

  <steps>
    <wflash value="hub_application.hex" comment="Прошивка ПО" />
  </steps>
</target>
```

- **`name`** — название цели (заголовок).
- **`description`** — краткое описание цели (показывается на экране прошивки).
- **`readme`** — подробное описание цели: `file="..."` или `value="..."` (если не задано — берётся из проекта).
- **`photo`** — изображение платы/подключения (для визуального сравнения).
- **`doc`** — документация цели (файл или URL).
- **`cathegory`** — категория/группа целей.
- **`type`** — если задано, переопределяет архитектуры проекта (для цели).
- **`options`** — опции цели.
- **`input`** — поле ввода пользователя (см. ниже).
- **`steps`** — последовательность шагов.
- **Любой другой элемент** (напр. `device`, `id`, версия ПО) становится
  **аргументом цели**: `<device value="X" />` → плейсхолдер `{device}`.
  Аргумент `id` используется как ключ сохранения настроек (`project:file:id`).

### Поле ввода `<input>`

```xml
<input value="int" default="0" id="getcall.counter" autoincrement="1" />
```

| Атрибут | По умолчанию | Описание |
|---------|--------------|----------|
| `name` | `input` | имя параметра → плейсхолдер `{input}` |
| `value` | — | тип ввода: `str`, `int`, `int32/48/64`, `hex32/48/64`, `MAC`, `ip` |
| `default` | — | значение по умолчанию |
| `id` | — | ключ сохранения введённого значения |
| `comment` | — | пояснение |
| `autoincrement` | `0` | можно увеличивать кнопкой `+` |

Тип проверяет и преобразует значение (`InputType`). Для числовых типов доступен
автоинкремент (например, серийных номеров).

## Шаги (`<steps>`)

Каждый дочерний элемент — **шаг** одного из видов:

| Элемент | Назначение |
|---------|-----------|
| `<имя-команды ... />` | выполнить команду; атрибуты (кроме `comment`) → аргументы `{имя}` |
| `<set name="..." value="..." />` | присвоить переменную окружения |
| `<if cond="..."> … <else> … </else> </if>` | ветвление |

Команда:

```xml
<steps>
  <erase comment="Очистка" />
  <wflash value="hub_application.hex" comment="Прошивка ПО" />
</steps>
```

`comment` — подпись шага; остальные атрибуты становятся аргументами шага.
Имя команды разрешается по реестру: сначала у **выбранного программатора**,
затем среди утилит/встроенных (см. [external-commands.md](external-commands.md)).

### Присвоение `<set>`

```xml
<set name="greet" value="hello-{transport}" />
```

Значение — шаблон; `{переменные}` подставляются **на момент выполнения**
(включая выходы предыдущих команд). Переменная попадает в окружение запуска
и доступна далее в `{...}` и в условиях `if`.

### Ветвление `<if>` / `<else>`

```xml
<if cond="transport == net">
  <message value="сетевой путь" />
  <else>
    <message value="программатор" />
  </else>
</if>
```

Ветка выбирается при **построении плана этапов** — по текущим опциям/GUI.
Изменение опций в GUI пересчитывает список этапов. Вложенные `if` допускаются.

### Условия (выражения)

Условие в `if cond` — выражение над переменными окружения:

| Форма | Смысл |
|-------|-------|
| `name` | переменная задана и непуста / не `0` / не `false` |
| `!expr` | логическое НЕ |
| `a && b`, `a \|\| b` | логика И / ИЛИ |
| `a == b`, `a != b`, `a < b`, `a > b`, `a <= b`, `a >= b` | сравнение (числа — численно, иначе строкой) |
| `'текст'`, `"текст"` | строковый литерал |
| `( … )` | группировка |

Совместимость: в сравнениях неизвестный идентификатор справа трактуется как
литерал, поэтому `transport == net` и `transport == 'net'` равнозначны.

## Как выбирается программатор

1. Берутся архитектуры цели (`type` цели) или проекта.
2. Среди загруженных программаторов выбираются поддерживающие их.
3. Пользователь выбирает инструмент; выбор запоминается для проекта.

## Примеры

Простой (STM32, один шаг):

```xml
<project>
  <name value="Хаб" />
  <type value="stm32" />
  <target>
    <name value="Прошивка" />
    <device value="STM32F107CGT6" />
    <cathegory value="0" />
    <steps>
      <wflash value="hub_application.hex" comment="Прошивка ПО" />
    </steps>
  </target>
</project>
```

С полем ввода и категорией:

```xml
<project>
  <name value="Кнопка вызова" />
  <id value="20240814_getline" />
  <type value="pic" />
  <target>
    <name value="Прошивка" />
    <device value="16F1503" />
    <cathegory value="0" />
    <input value="int" default="0" id="getcall.counter" autoincrement="1" />
    <steps>
      <wflash value="getcall-firmware.X.production.hex" comment="Прошивка ПО" />
    </steps>
  </target>
</project>
```

См. также: [Формат `.etool`](etool.md) · [Внешние команды](external-commands.md).
